## 1. Product in one paragraph

Community Health Workers (CHWs) write messy field notes that contain names, phone numbers and locations. Outbreak reporting is late because those notes must be re-typed into structured forms, and they cannot be uploaded as-is without leaking patient identity. OutbreakPulse turns a raw field note into a structured, de-identified case record **on the device**, works with no connectivity, and syncs only the de-identified record. In the cloud, county surveillance officers get deterministic cluster detection and an AI-drafted situation report built from aggregates, never from patient text.

**Tagline:** Patient data stays on the device. Population intelligence lives in the cloud.

**Scenario scope (do not widen):** one syndrome, acute watery diarrhoea (AWD) with suspected cholera, in a fictional county. Depth over breadth.

## 4. Architecture

### 4.1 Stack

- Next.js (App Router, TypeScript strict) with **`output: 'export'`** (fully static, no SSR, no server actions, no route handlers, no dynamic route segments). Served by Firebase Hosting.
- Tailwind CSS v4.
- Firebase JS SDK v13: `firebase/app`, `firebase/app-check`, `firebase/auth`, `firebase/firestore`, `firebase/remote-config`, `firebase/ai`.
- Hand-written service worker (`public/sw.js` template, precache manifest generated by `scripts/generate-sw.mjs` after `next build`). No PWA plugin.
- Vitest for unit tests. ESLint. GitHub Actions CI.

### 4.2 The three inference tiers

| Tier | Engine | Input it may receive | Used for |
|---|---|---|---|
| Rules | Deterministic TypeScript (`src/lib/triage/rules.ts`) | Structured fields | Risk level floor, always available, offline, instant |
| On-device | Gemini Nano through `firebase/ai` | **Raw note** (may contain PII) | Extraction, PII span detection, risk explanation |
| Cloud | Gemini through `firebase/ai` | **De-identified data only** | Extraction fallback on scrubbed text, county SitRep from aggregates |

### 4.3 Model instances (`src/lib/ai/models.ts`)

| Name | `InferenceMode` | Why this mode |
|---|---|---|
| `rawNoteModel` | `ONLY_ON_DEVICE` | Receives raw text. `ONLY_ON_DEVICE` guarantees the SDK can never fall back to the cloud with identifiable data. |
| `scrubbedNoteModel` | `PREFER_ON_DEVICE` | Receives text already scrubbed by the deterministic redactor. Uses Nano when present, cloud otherwise. This is the hybrid fallback judges expect to see. |
| `sitrepModel` | `ONLY_IN_CLOUD` | Population-level reasoning over aggregates. Larger cloud model, name from Remote Config. |

All three use structured output: `onDeviceParams.promptOptions.responseConstraint` and `inCloudParams.generationConfig.responseSchema` with `responseMimeType: "application/json"`, sharing one schema from `src/lib/ai/schemas.ts`. Every response is parsed and validated (`zod`); invalid output is a handled error, never a crash.

Every AI call records `response.inferenceSource` (`ON_DEVICE` or `IN_CLOUD`) and wall-clock latency, and the UI shows both.

### 4.4 Field note pipeline (`src/lib/triage/pipeline.ts`)

```
raw note
  -> scrubDeterministic()          always, local, sync (phones, emails, IDs, GPS, dates of birth, titled names)
  -> detect Nano availability      LanguageModel.availability() from Chrome Prompt API
  -> branch:
     A. Nano available            rawNoteModel(raw)        -> extraction + PII spans -> apply spans
     B. Nano missing, online      privacy gate: show scrubbed text, user confirms -> scrubbedNoteModel(scrubbed)
     C. Nano missing, offline     keyword extraction (extract.ts) now; enqueue AI enrichment of the scrubbed text for later
  -> evaluateRules(fields)         deterministic risk floor
  -> mergeRisk(rules, ai)          AI may raise risk with a stated reason, never lower it
  -> CaseRecord (de-identified)    written to Firestore without awaiting the server
```

Rules that must never be broken:
- The raw note is **never** written to Firestore, localStorage, logs, analytics, or any network request. It lives in component state only and is cleared after save.
- Nothing reaches `scrubbedNoteModel` or `sitrepModel` that has not passed `scrubDeterministic()`.
- The rules engine output is the floor. A HIGH from rules stays HIGH.
- Triage submission never awaits a network call.

### 4.5 Surveillance pipeline (`src/lib/surveillance/`)

1. Query `cases` for the county over the window (Remote Config `cluster_window_days`).
2. `aggregate.ts`: deterministic counts per sub-county per day, baseline vs. recent window, attack signal.
3. `detect.ts`: alert status per sub-county from Remote Config thresholds (`NORMAL`, `WATCH`, `CRITICAL`). Pure functions, fully unit tested.
4. `sitrep.ts`: `sitrepModel` receives **only** the aggregate table and alert statuses. It returns an executive summary, hypotheses to investigate (never asserted transmission chains) and resource recommendations.
5. The report is saved to `sitreps` with the exact aggregate input used, for auditability.

### 4.6 Offline and sync

- Firestore: `initializeFirestore(app, { localCache: persistentLocalCache({ tabManager: persistentMultipleTabManager() }) })`.
- Writes use `setDoc(doc(collection(...)), data)` **without awaiting** while offline. Pending state comes from `onSnapshot(..., { includeMetadataChanges: true })` and `hasPendingWrites`.
- Deferred AI enrichment jobs live in IndexedDB (`src/lib/offline/queue.ts`) and replay on the `online` event.
- Auth (anonymous) and Remote Config need one online launch. After that the field flow works fully offline. Document this in the README.
- Service worker precaches every file in `out/` and serves navigations cache-first with network revalidation.

### 4.7 Remote Config parameters (defaults in `src/lib/firebase/remote-config.ts`)

| Key | Type | Default | Purpose |
|---|---|---|---|
| `cluster_window_days` | number | 7 | Recent window for detection |
| `cluster_baseline_days` | number | 14 | Baseline window before the recent window |
| `cluster_watch_threshold` | number | 3 | Cases in window that trigger WATCH |
| `cluster_critical_threshold` | number | 6 | Cases in window that trigger CRITICAL |
| `sitrep_model` | string | `gemini-3.8-flash` | Cloud model for SitRep |
| `privacy_gate_required` | boolean | true | Require explicit confirmation before cloud extraction |

## 7. Design system

- Minimal, clinical, solid colors, high readability outdoors. Mobile first (CHWs use phones), desktop for surveillance.
- Fonts: self-hosted via `next/font` so they work offline. Primary: Google Sans Flex if available in `next/font/google`, otherwise Inter. Mono: Google Sans Code if available, otherwise JetBrains Mono. Mono for case IDs, timestamps, latency, counts.
- Tokens (CSS variables in `globals.css`):
  - Background `#FFFFFF`, surface `#F8FAFC`, border `#E2E8F0` (1px solid)
  - Text primary `#0F172A`, secondary `#475569`
  - Brand `#0F766E`
  - Low `#15803D` on `#F0FDF4`, Medium `#B45309` on `#FFFBEB`, High `#B91C1C` on `#FEF2F2`
- Bans: gradients, glows, heavy shadows, emojis, ALL-CAPS labels (store `HIGH`, display `High risk`), em-dashes in UI copy, decorative badges, gratuitous animation.
- Every async view has loading, empty, error and offline states.
- Accessibility: WCAG AA contrast, visible focus rings, labels on every input, touch targets 44px minimum, color is never the only signal (risk badges include text).
- No third-party logos or trademarks (no WHO, ministry, CDC marks). Text references to public case definitions are allowed without logos.

## 8. Engineering standards

- TypeScript `strict: true`, no `any`, no non-null assertions without a comment explaining why.
- Validate every external boundary with `zod`: AI output, Firestore reads, Remote Config values.
- Errors are typed results (`{ ok: true, value } | { ok: false, error }`) inside `lib/`; components render the error state.
- No `console.log` in committed code except the App Check debug token path in development.
- Small pure functions, tested. Tests required for: rules engine, redaction, risk merge, aggregation, detection.
- Secrets: Firebase web config is public by design but lives in `.env.local` (gitignored) via `NEXT_PUBLIC_*`. `.env.example` lists every key with placeholders. Never commit debug tokens, service accounts, or `.env.local`.
- Commits: Conventional Commits in English (`feat:`, `fix:`, `docs:`...). No AI attribution lines, no co-author trailers, no tool signatures.

### Definition of done for any change

1. `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` all pass.
2. Works with DevTools network set to Offline for the field flow.
3. Works in a Chrome profile without Gemini Nano (cloud fallback visible) and with it (on-device visible).
4. No raw note text appears in Firestore, network requests or console.
